# DEV-002 — Local Environment and PostgreSQL Workflow

## Objective

Provide a repeatable and guarded local setup for project configuration, dependency installation, and PostgreSQL 16 development workflows.

## Overview

DEV-002 added committed environment templates at the repository root and in both application workspaces. `make env-setup` copies only missing local files, preserving any existing configuration. The examples keep local database credentials aligned while ensuring actual `.env` files remain ignored.

The new `compose.yaml` defines a PostgreSQL 16 development service with:

- A port bound only to `127.0.0.1`.
- The persistent `penny_saved_postgres_data` named volume.
- A `pg_isready` health check.
- Database values supplied explicitly by the root `.env` file.

The root Makefile now provides help, environment setup, dependency installation, database lifecycle, and Alembic workflow targets. Migration targets are present but explain that DEV-005 must add Alembic configuration before they can run.

## Main Commands

```text
make help
make env-setup
make install
make db-up
make db-down
make db-logs
make db-reset
make db-upgrade
make db-downgrade
make db-revision message="describe_change"
```

`make db-up` waits for PostgreSQL to become healthy. `make db-down` removes the local container while preserving its named data volume.

## Safety Controls

- `make env-setup` never overwrites an existing `.env` file.
- PostgreSQL is not exposed on every network interface.
- `make db-reset` refuses CI execution and requires the exact confirmation word `reset`.
- Reset deletes only the explicitly named local PostgreSQL volume.
- Reset, downgrade, and revision creation require `APP_ENV=development` and a localhost database URL.
- `make db-downgrade` requires the exact confirmation word `downgrade`.
- Test configuration must provide a separate explicit `TEST_DATABASE_URL`; it is not inferred from the development URL.
- Migration commands fail with an actionable message until DEV-005 supplies Alembic configuration.

## What It Achieved

- A contributor has one documented path for creating local configuration and installing dependencies.
- The local database definition is persistent, health-checked, and accessible only through loopback.
- Normal database shutdown preserves data.
- Destructive and reverse-migration operations have explicit environment, host, and confirmation guards.
- Tool prerequisites produce actionable errors instead of silently installing system software.

## Verification

The following were verified during implementation:

- `make help` lists the documented targets.
- `make env-setup` creates missing files and leaves them ignored by Git.
- Frontend and backend installation targets execute successfully with supported runtimes.
- The local-database guard accepts the development example configuration.
- `compose.yaml` parses successfully and contains the required image, loopback port, named volume, and health check.
- Existing frontend and backend formatting, linting, typing, tests, and build checks remain green.
- `git diff --check` passes.

## Limitation and Follow-up

Docker was not installed in the implementation environment, so the PostgreSQL container could not be launched there. The Compose definition was structurally validated, and `make db-up` correctly reported the missing Docker prerequisite. DEV-005 will add the Alembic configuration and migrations used by the database revision, upgrade, and downgrade targets.
